## 📦 Описание скриптов

### 1. `analyze_unused_scripts.sh`

**Что делает:**
- Сканирует все `.gd` файлы в `scripts/`
- Проверяет, используются ли они в других скриптах, сценах, ресурсах
- Выводит список неиспользуемых файлов

**Пример вывода:**
```
✅ ИСПОЛЬЗУЕТСЯ: scripts/GameController.gd (15 упоминаний)
❌ НЕИСПОЛЬЗУЕМЫЙ: scripts/OldScript.gd
```

**Предупреждение:** Может давать ложные срабатывания для скриптов, загружаемых динамически через `load()`.

---

### 2. `analyze_unused_scenes.sh`

**Что делает:**
- Сканирует все `.tscn` файлы в `scenes/`
- Проверяет, инстанцируются ли они в коде или других сценах
- Исключает главную сцену `Game.tscn`

**Пример вывода:**
```
✅ ИСПОЛЬЗУЕТСЯ: scenes/PayoutPopup.tscn (3 упоминания)
❌ НЕИСПОЛЬЗУЕМАЯ: scenes/OldPopup.tscn
```

---

### 3. `analyze_autoloads.sh`

**Что делает:**
- Читает все autoload синглтоны из `project.godot`
- Проверяет, используются ли они в коде (поиск по `AutoloadName.`)
- Показывает примеры использования

**Пример вывода:**
```
🔍 Проверяю: EventBus
  ✅ Используется (42 упоминания)
  Примеры:
    GameController.gd: EventBus.show_toast_error.emit(...)
```

---

### 4. `analyze_unused_assets.sh`

**Что делает:**
- Сканирует ресурсы в `assets/` (png, jpg, svg, tres)
- Проверяет, используются ли они в коде/сценах
- Предупреждает о возможных динамических загрузках

**Пример вывода:**
```
✅ Используется: assets/ui/button.png (5 упоминаний)
❌ НЕИСПОЛЬЗУЕМЫЙ: assets/old_icon.png
```

**⚠️ ВНИМАНИЕ:** Проверьте вручную перед удалением! Некоторые ресурсы могут загружаться через `load("res://...")`.

---

### 5. `analyze_all.sh` (главный скрипт)

**Что делает:**
- Запускает все 4 скрипта последовательно
- Создает единый отчет в `tools/unused_analysis_report.txt`
- Выводит итоговую статистику

**Рекомендуемый workflow:**
1. Запустить `./tools/analyze_all.sh`
2. Просмотреть отчет: `cat tools/unused_analysis_report.txt`
3. Вручную проверить найденные файлы
4. Сделать backup: `git commit -am "backup before cleanup"`
5. Удалить ненужные файлы
6. Протестировать проект (F5 в Godot)

## 🧪 GUT тесты

### `test_unused_code_detection.gd`

GDScript тест для глубокого анализа кода (использует GUT framework).

**Запуск:**
```bash
cd "/Users/vaaceslav/Личное Вячеслав/GitHub/Baccarat"
godot --path . --headless --script addons/gut/gut_cmdln.gd -gtest=tests/test_unused_code_detection.gd
```

**Что проверяет:**

1. **Неиспользуемые публичные методы**
   - Находит методы без `_` префикса
   - Проверяет, вызываются ли они где-то

2. **Неиспользуемые переменные**
   - Рекомендует включить Godot warnings

3. **Дублирование кода**
   - Выводит рекомендации по поиску копипасты

4. **Мертвый код (unreachable)**
   - Ищет код после `return`
   - Находит недостижимые ветки

5. **TODO/FIXME комментарии**
   - Сканирует все файлы
   - Выводит список устаревших комментариев

6. **Общая статистика проекта**
   - Количество скриптов
   - Строк кода
   - Функций
   - Комментариев

## 📊 Интерпретация результатов

### ✅ Зеленые отметки (Используется)
- Файл/метод активно используется
- **Действие:** Оставить как есть

### ❌ Красные отметки (Не используется)
- Потенциально неиспользуемый элемент
- **Действие:**
  1. Проверить вручную
  2. Убедиться, что не загружается динамически
  3. Проверить через git: `git log -- <файл>`
  4. Удалить если уверены

### ⚠️ Желтые предупреждения (Требует проверки)
- Найдены подозрительные паттерны
- **Действие:** Проверить и возможно рефакторить

## 🛡️ Безопасность

**Перед удалением файлов:**

1. ✅ Сделайте git commit:
   ```bash
   git add .
   git commit -m "backup before cleanup"
   ```

2. ✅ Создайте backup:
   ```bash
   cp -r . ../Baccarat_backup
   ```

3. ✅ Протестируйте проект после каждого удаления:
   - Запустите игру (F5)
   - Проверьте все основные функции
   - Запустите тесты

4. ✅ Проверьте динамические загрузки:
   ```bash
   grep -r "load(" scripts/ | grep "res://"
   ```

## 🐛 Известные ограничения

1. **Динамические загрузки не отслеживаются**
   - Файлы, загружаемые через `load()` или `preload()` со строками
   - Решение: проверить вручную

2. **Рефлексия не учитывается**
   - Вызовы через `call()`, `get()`, `set()`
   - Решение: поиск по строкам в коде

3. **Ресурсы в .tres/.tscn файлах**
   - Сложная структура вложенности
   - Решение: дополнительная проверка через Godot Editor

4. **Методы, вызываемые через сигналы**
   - Автоматические подключения в сценах
   - Решение: проверка `@onready` и `connect()`
