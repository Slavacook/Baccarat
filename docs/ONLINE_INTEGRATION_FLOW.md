## Схема интеграции: онлайн-обучение (Godot -> Server -> Dashboard)

## 1) Архитектурная цепочка

Поток live-данных:

1. **Game Logic** генерирует игровые изменения (карты, ошибки, выбор победителя, выплаты).
2. **EventBus** рассылает внутренние сигналы (`round_started`, `action_error`, и т.д.).
3. **OnlineLiveEventBridge** собирает snapshot состояния стола и legacy-события.
4. **LiveSessionClient** отправляет JSON через WebSocket `/ws/sessions/{session_id}`.
5. **FastAPI server** принимает событие от дилера и broadcast-ит тренеру/участникам сессии.
6. **Trainer dashboard**:
   - строит визуальный live-view стола по `table_state` (canonical snapshot);
   - использует legacy-события для ленты/обратной совместимости.

## 2) Роли сообщений

- `table_state` — источник правды для визуального состояния стола.
- `round_started`, `action_performed`, `error_occurred`, `round_completed` — legacy-поток для лога, UX-меток и совместимости.

Подробный контракт:

- `docs/ONLINE_PROTOCOL.md`
- `docs/TABLE_STATE_CONTRACT_V1.md`

## 3) Принцип стабильности при reconnect

Чтобы dashboard не рассинхронизировался при потере пакетов:

- каждый `table_state` содержит `event_seq` (монотонный счетчик);
- dashboard применяет только события с `event_seq > last_seq` для конкретного дилера;
- при reconnect рекомендуется отправлять последний snapshot (`table_state_sync`) перед дальнейшим live-потоком;
- дубликаты (одинаковый `event_seq`) считаются нормальными и должны игнорироваться.

## 4) Границы ответственности

- **Godot-клиент**: формирует корректный snapshot (`table_state`) и отправляет при значимых изменениях.
- **Сервер**: маршрутизирует, при необходимости кеширует последний snapshot по дилеру/сессии.
- **Dashboard**: хранит state по `dealer_id`, применяет seq-правила, рисует стол без бизнес-логики баккары на фронте.

## 5) Что не меняется на этапе спецификации

- Текущая таблица агрегатов (`/api/sessions/{id}/results`) остается без изменений.
- HTTP submit результатов раунда остается основным источником пост-раунд аналитики.
- Новая модель затрагивает только live-view слой.
