> **Раздел плана:** 4.1  
> **Дата создания:** 2026-04-12  
> **Статус:** Детализация  
> **Зависимости:** Раздел 1 (Авторизация), Раздел 2 (Система комнат), Раздел 3 (Живая сессия)

---

## 1. Обзор

Асинхронная тренировка — это режим, при котором дилер заходит в комнату в любое время (не во время живой сессии) и тренируется в своём темпе. Нет таймера, нет синхронизации с другими, но результаты всё равно пишутся на сервер и попадают в общую таблицу лидеров.

### Ключевые отличия от живой сессии

| Параметр | Живая сессия | Асинхронная тренировка |
|----------|--------------|------------------------|
| **Таймер** | Есть, обратный отсчёт | Нет, играй сколько хочешь |
| **Синхронизация** | Все получают одинаковые раздачи | Каждый получает случайные раздачи |
| **Seed** | MASTER_SEED от сервера | Клиент генерирует свой seed |
| **Начало** | По команде тренера | По желанию дилера |
| **Конец** | По таймеру/лимиту/тренеру | По желанию дилера |
| **WebSocket** | Требуется (real-time) | Не требуется (только HTTP) |
| **Таблица лидеров** | Общий рейтинг | Общий рейтинг (одинаковые правила подсчёта) |
| **Результаты** | Отправляются после сессии | Отправляются после каждого раунда |

## 3. Поток асинхронной тренировки

### 3.1 Начало тренировки

```
ДИЛЕР:
1. В лобби комнаты нажимает "Начать тренировку"
2. Клиент генерирует session_id (локальный UUID)
3. Клиент отправляет на сервер: POST /api/rooms/{code}/async-sessions
4. Сервер создаёт запись (status = active, type = async)
5. Сервер возвращает session_id
6. Дилер начинает играть

ДИЛЕР (во время игры):
1. После каждого раунда отправляет: POST /api/async-sessions/{id}/results
2. Сервер сохраняет результат
3. Сервер возвращает обновлённую статистику дилера
4. UI обновляет "Точность: 87%, Раундов: 24"

ДИЛЕР (завершение):
1. Нажимает "Завершить тренировку"
2. Клиент отправляет: POST /api/async-sessions/{id}/end
3. Сервер обновляет статус = completed
4. Дилер видит итоговые результаты
```

### 3.2 Визуальная схема

## 4. Отличие записи результатов от живой сессии

### 4.1 Сравнение

| Параметр | Живая сессия | Асинхронная тренировка |
|----------|--------------|------------------------|
| **Когда отправляется** | После каждого раунда (WebSocket) | После каждого раунда (HTTP POST) |
| **Batch-отправка** | Нет, каждый раунд отдельно | Нет, каждый раунд отдельно |
| **Кэширование при обрыве** | Да (локальный кэш → flush) | Да (локальный кэш → retry) |
| **Seed раздач** | От сервера (MASTER_SEED) | Локальный (клиент генерирует) |
| **Верификация seed** | Сервер раскрывает MASTER_SEED после сессии | Нет (результат доверяем) |
| **Таймер** | Фиксируется сервером | Фиксируется клиентом |

### 4.2 Формат результата раунда (одинаковый для обоих режимов)

```json
{
  "round_number": 1,
  "session_type": "async",
  "accuracy": 100.0,
  "errors": [],
  "time_spent_seconds": 18,
  "player_third_card": true,
  "banker_third_card": false,
  "player_third_correct": true,
  "banker_third_correct": null,
  "winner_chosen": "Player",
  "winner_correct": true,
  "payout_correct": true,
  "lives_remaining": 7,
  "client_timestamp": "2026-04-12T15:30:28Z"
}
```

**Поле `session_type`:** `"live"` или `"async"` — позволяет фильтровать в аналитике.

### 4.3 Валидация на сервере

Сервер проверяет:
1. Сессия существует и активна
2. Дилер принадлежит комнате сессии
3. `round_number` — последовательный (не пропущен)
4. `accuracy` в диапазоне 0-100
5. `time_spent_seconds` > 0
6. `client_timestamp` — не в будущем, не старше 24 часов

```python
# server/validators/async_result.py
def validate_async_round_result(result: dict, session: AsyncSession, dealer: Dealer):
    errors = []
    
    if not (0 <= result.get("accuracy", -1) <= 100):
        errors.append("Accuracy must be between 0 and 100")
    
    if result.get("time_spent_seconds", 0) <= 0:
        errors.append("Time spent must be positive")
    
    # Проверка последовательности раундов
    last_round = db.query(func.max(RoundResult.round_number)).filter(
        RoundResult.session_id == session.id,
        RoundResult.dealer_id == dealer.id
    ).scalar()
    
    expected_round = (last_round or 0) + 1
    if result.get("round_number") != expected_round:
        errors.append(f"Expected round {expected_round}, got {result.get('round_number')}")
    
    # Проверка времени
    client_time = datetime.fromisoformat(result["client_timestamp"])
    now = datetime.utcnow()
    if client_time > now + timedelta(seconds=30):
        errors.append("Client timestamp is in the future")
    
    if client_time < now - timedelta(hours=24):
        errors.append("Client timestamp is too old")
    
    return errors
```

## 5. Лимиты асинхронной тренировки

### 5.1 Ограничения

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| Макс. раундов за одну async-сессию | 200 | Защита от бесконечных сессий |
| Макс. async-сессий в день | 10 | Защита от спама результатами |
| Макс. раундов в день (суммарно) | 500 | Защита от накрутки таблицы лидеров |
| Мин. время раунда | 3 секунды | Защита от ботов/автокликеров |
| Макс. время async-сессии | 2 часа | Автоматическое завершение |
| Макс. одновременных async-сессий | 1 | Одна сессия за раз |

### 5.2 Автоматическое завершение

| Триггер | Действие |
|---------|----------|
| Достигнут лимит раундов (200) | Автозавершение, уведомление дилера |
| Достигнут лимит времени (2 часа) | Автозавершение, уведомление дилера |
| Дилер не отправлял результаты 30 мин | Автозавершение "по таймауту" |
| Дилер нажал "Завершить" | Нормальное завершение |

## 7. Может ли тренер запустить асинхронное задание?

### 7.1 Концепция "асинхронного задания"

Тренер может назначить задание, которое дилеры выполняют в своём темпе (не во время живой сессии):

```
📝 ЗАДАНИЕ: "3-я карта Банкира"
Тип: Асинхронное
Срок: до пятницы
Цель: 30 раздач с точностью 90%+
```

### 7.2 Как это работает

```
1. Тренер создает задание с типом "async"
2. Дилер видит задание в лобби комнаты
3. Дилер начинает async-тренировку
4. Сервер отслеживает прогресс по заданию
5. Когда дилер достиг цели → задание выполнено
6. Тренер видит статус: "Выполнил / Не выполнил / Просрочено"
```

## 8. База данных — таблицы асинхронных сессий

### 8.1 Таблица `async_sessions`

```sql
CREATE TABLE async_sessions (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    room_id             UUID NOT NULL REFERENCES rooms(id) ON DELETE CASCADE,
    dealer_id           UUID NOT NULL REFERENCES dealers(id),
    status              VARCHAR(20) DEFAULT 'active',  -- active, completed, timeout, limit_reached
    started_at          TIMESTAMPTZ DEFAULT NOW(),
    ended_at            TIMESTAMPTZ,
    end_reason          VARCHAR(30),  -- dealer_end, round_limit, time_limit, timeout
    rounds_completed    INT DEFAULT 0,
    total_time_seconds  INT DEFAULT 0,
    created_at          TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_async_sessions_room ON async_sessions(room_id);
CREATE INDEX idx_async_sessions_dealer ON async_sessions(dealer_id);
CREATE INDEX idx_async_sessions_started_at ON async_sessions(started_at);
```

### 8.2 Таблица `daily_round_limits` (отслеживание дневных лимитов)

```sql
CREATE TABLE daily_round_limits (
    id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    dealer_id           UUID NOT NULL REFERENCES dealers(id),
    date                DATE NOT NULL,
    rounds_completed    INT DEFAULT 0,
    sessions_count      INT DEFAULT 0,
    total_xp_earned     INT DEFAULT 0,
    
    UNIQUE(dealer_id, date)
);

CREATE INDEX idx_daily_limits_dealer_date ON daily_round_limits(dealer_id, date);
```

## 11. Обработка ошибок и краёв

### 11.1 Потеря соединения

| Сценарий | Поведение |
|----------|----------|
| Краткий обрыв (< 30 сек) | Retry отправки результата (3 попытки) |
| Средний обрыв (30 сек - 5 мин) | Кэшировать локально → отправить при восстановлении |
| Долгий обрыв (> 30 мин) | Автозавершение сессии "по таймауту" |

### 11.2 Краш приложения

```
1. Приложение крашнулось
2. Результаты в локальном кэше (user://async_cache_{session_id}.json)
3. При следующем запуске:
   - Проверить, активна ли сессия на сервере
   - Если активна → flush кэша
   - Если завершена → создать новую сессию, кэш потерян (предупредить пользователя)
```

### 11.3 Дневной лимит достигнут во время сессии

```
1. Дилер играет, достигает 500 раундов за день
2. Сервер отклоняет следующий результат: 429 "Daily limit reached"
3. Клиент показывает: "Дневной лимит достигнут. Тренировка остановлена."
4. Сессия завершается автоматически
5. Лимит сбрасывается в полночь (по UTC)
```

## 12. Тест-кейсы

### 12.1 Создание async-сессии

| # | Сценарий | Ожидаемый результат |
|---|----------|---------------------|
| 1 | Дилер создаёт async-сессию | 201, session_id, лимиты возвращены |
| 2 | Дневной лимит раундов достигнут | 429, "Daily limit reached" |
| 3 | Дневной лимит сессий достигнут | 429, "Session limit reached" |
| 4 | Комната архивирована | 410, "Room archived" |
| 5 | Уже есть активная async-сессия | 409, "Session already active" |

### 12.2 Отправка результатов

| # | Сценарий | Ожидаемый результат |
|---|----------|---------------------|
| 1 | Валидный результат → отправка | 200, stat обновлены |
| 2 | Время раунда < 3 сек | 422, "Minimum round time: 3 seconds" |
| 3 | Лимит раундов сессии (200) | 429, "Session round limit reached" |
| 4 | Дилер не в этой комнате | 403, "No access" |
| 5 | Неправильный round_number | 422, "Expected round X, got Y" |

### 12.3 Завершение

| # | Сценарий | Ожидаемый результат |
|---|----------|---------------------|
| 1 | Дилер завершил вручную | 200, status = completed |
| 2 | Лимит раундов (200) | Автозавершение, status = completed |
| 3 | Лимит времени (2 часа) | Автозавершение, status = completed |
| 4 | Таймаут (30 мин бездействия) | Автозавершение, status = timeout |
