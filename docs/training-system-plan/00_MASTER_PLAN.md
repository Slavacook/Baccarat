# План разработки: Система тренировки с тренером

> **Дата создания:** 2026-04-12  
> **Статус:** План утверждён, ожидает детализации и реализации  
> **Версия:** 1.0 (черновик)

---

## 📋 Общее описание

Проект по превращению одиночного тренажёра Баккара в **платформу для группового обучения** с тренером.

### Цель

Создать систему, где:
- **Тренер** создаёт комнату, запускает тренировки, видит дашборд с результатами всех дилеров
- **Дилеры** входят по коду, тренируются синхронно или асинхронно, соревнуются в таблице лидеров
- **Сервер** хранит данные, синхронизирует сессии, предоставляет API и дашборд

### Платформы клиента

- 📱 **iOS** — сборка для iPhone
- 🤖 **Android** — сборка для Android
- 💻 **Desktop** (macOS/Windows/Linux) — по желанию в будущем

### Сервер

- Игра (Godot-клиент) **больше не лежит на сервере**
- Сервер хранит только: базу данных, API, дашборд тренера
- Клиент скачивается как приложение и подключается к серверу через HTTPS

## 3. Живая синхронная сессия

### Описание

Тренер запускает тренировку для всех участников одновременно. Таймер стартует синхронно, по истечении — игра останавливается, результаты фиксируются.

### Что нужно решить

- [ ] **Запуск сессии** — тренер нажимает "Старт" → все участники получают сигнал
- [ ] **Экран ожидания** — дилеры видят "Ожидание старта..." до команды тренера
- [ ] **Синхронный таймер** — обратный отсчёт одинаковый у всех (15/30/45/60 мин)
- [ ] **Одинаковые раздачи** — seed-based генерация, все получают одинаковые карты
- [ ] **Автоматическая остановка** — по истечении таймера игра останавливается у всех
- [ ] **Отправка результатов** — после остановки результаты летят на сервер
- [ ] **Обработка обрывов** — дилер отключился → результат сохраняется, можно продолжить
- [ ] **Опоздавшие** — дилер вошёл через 10 минут → начинает играть, таймер идёт с общего старта

### Что расширить

- [ ] Детально описать протокол синхронизации (WebSocket? polling? push-уведомления?)
- [ ] Описать механизм seed-генерации раздач (как обеспечить одинаковость)
- [ ] Описать формат данных результата раунда (что отправляется на сервер)
- [ ] Описать поведение при потере соединения (retry, кэширование, конфликты)
- [ ] Описать UI-состояния дилера во время сессии (ожидание, игра, пауза, завершение)
- [ ] Описать UI тренера во время сессии (мониторинг в реальном времени)
- [ ] Описать процесс завершения сессии (что происходит на сервере, что у клиента)
