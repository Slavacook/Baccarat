# 📋 РУЧНОЕ ТЕСТИРОВАНИЕ PayoutQueueHandler

## Цель тестирования
Проверить, что рефакторинг `PayoutQueueHandler` не сломал функциональность обработки очереди выплат.

---

## 🎯 ТЕСТ 1: Определение победителя и создание очереди выплат

### Что проверяем:
- После раздачи карт определяется победитель
- Создается очередь выплат (основная ставка + пары, если есть)
- Очередь сохраняется в `GameDataManager`

### Шаги для тестирования:

1. **Запустите игру**
   - Откройте проект в Godot
   - Нажмите F5 или кнопку "Play"

2. **Сделайте ставку**
   - Выберите тип ставки (Player/Banker/Tie)
   - Разместите фишку на столе
   - Если есть гости, они тоже могут сделать ставки

3. **Начните раунд**
   - Нажмите кнопку "Начать" (или Space)
   - Дождитесь раздачи первых 4 карт (Player 2 карты, Banker 2 карты)

4. **Определите победителя**
   - Если натуральная (8 или 9) - победитель определяется сразу
   - Если нет - дождитесь третьих карт (если нужны)
   - Победитель определяется автоматически

5. **Проверьте создание очереди выплат**
   - Откройте консоль Godot (Output)
   - Найдите сообщения типа:
     ```
     💰 PayoutQueueManager: добавлена ставка Player[0] (stake=..., payout=..., ✅ ВЫИГРЫШ)
     💰 PayoutQueueManager: добавлена ставка Banker[0] (stake=..., payout=..., ❌ ПРОИГРЫШ)
     ```
   - Должны быть сообщения о добавлении ставок в очередь

### ✅ Ожидаемый результат:
- Победитель определяется корректно
- В консоли видны сообщения о создании очереди выплат
- Очередь содержит все ставки (выигрышные и проигрышные)

### ❌ Если не работает:
- Проверьте консоль на ошибки
- Убедитесь, что `WinnerSelectionHandler` вызывается
- Проверьте, что `PayoutQueueHandler` инициализирован

---

## 🎯 ТЕСТ 2: Подготовка выплат в ручном режиме

### Что проверяем:
- После определения победителя подготавливаются выплаты
- Создается новый `PayoutQueueManager`
- Настраивается `BetCollectionPhaseManager`
- Сохраняется состояние стола

### Шаги для тестирования:

1. **Повторите шаги 1-4 из ТЕСТА 1**
   - Сделайте ставку
   - Начните раунд
   - Определите победителя

2. **Проверьте подготовку выплат**
   - После определения победителя должна начаться подготовка выплат
   - В консоли должны быть сообщения:
     ```
     ✅ Создан новый PayoutQueueManager, ссылка обновлена в phase_manager
     ✅ BetCollectionPhaseManager настроен для раунда (победитель: Player, режим: COLLECT)
     ```

3. **Проверьте состояние стола**
   - Состояние стола должно быть сохранено в `TableStateManager`
   - Это происходит автоматически, проверьте консоль на ошибки

### ✅ Ожидаемый результат:
- Новый `PayoutQueueManager` создается
- `BetCollectionPhaseManager` настраивается корректно
- Состояние стола сохраняется без ошибок
- В консоли нет ошибок типа "PayoutQueueHandler не инициализирован"

### ❌ Если не работает:
- Проверьте, что `_prepare_payouts_manual()` вызывается
- Убедитесь, что `payout_queue_handler` не null
- Проверьте инициализацию в `_ready()`

---

## 🎯 ТЕСТ 3: Обновление видимости фишек

### Что проверяем:
- После подготовки выплат обновляется видимость фишек
- Оплаченные ставки скрываются
- Собранные проигрышные ставки скрываются
- Выигрышные и неоплаченные ставки остаются видимыми

### Шаги для тестирования:

1. **Повторите шаги 1-4 из ТЕСТА 1**
   - Сделайте ставку (например, на Player)
   - Начните раунд
   - Определите победителя (например, Player выиграл)

2. **Проверьте видимость фишек**
   - После определения победителя фишки должны остаться видимыми
   - Выигрышные фишки должны быть видимыми и кликабельными
   - Проигрышные фишки должны быть видимыми (для сбора)

3. **Оплатите выигрышную ставку**
   - Кликните на выигрышную фишку
   - Откроется `PayoutOverlay`
   - Выберите правильную сумму и нажмите "Выплатить"

4. **Проверьте скрытие оплаченной фишки**
   - После оплаты фишка должна исчезнуть
   - В консоли должно быть сообщение:
     ```
     💰 Фишка Player[0] скрыта (оплачена)
     ```

5. **Соберите проигрышную ставку**
   - Кликните на проигрышную фишку (например, Banker, если выиграл Player)
   - Фишка должна исчезнуть
   - В консоли должно быть сообщение:
     ```
     💰 Фишка Banker[0] скрыта (собрана)
     ```

6. **Проверьте отображение суммы ставки**
   - Рядом с каждой видимой фишкой должна быть метка с суммой ставки
   - Метка должна иметь черный фон с золотой рамкой
   - Сумма должна быть отформатирована (например, "1 000")

### ✅ Ожидаемый результат:
- Выигрышные фишки видимы и кликабельны
- Проигрышные фишки видимы для сбора
- Оплаченные фишки скрываются
- Собранные фишки скрываются
- Метки с суммами отображаются корректно

### ❌ Если не работает:
- Проверьте, что `update_chip_visibility()` вызывается
- Убедитесь, что `chip_visual_manager` не null
- Проверьте логику в `PayoutQueueHandler.update_chip_visibility()`

## 🎯 ТЕСТ 4: Обработка очереди выплат или сброс раунда

### Что проверяем:
- После оплаты всех ставок раунд сбрасывается
- Если есть еще выплаты в очереди, они обрабатываются
- Состояние игры корректно обновляется

### Шаги для тестирования:

1. **Повторите шаги 1-4 из ТЕСТА 1**
   - Сделайте несколько ставок (например, Player и Banker)
   - Начните раунд
   - Определите победителя

2. **Оплатите все ставки**
   - Оплатите все выигрышные ставки
   - Соберите все проигрышные ставки

3. **Проверьте сброс раунда**
   - После оплаты всех ставок раунд должен автоматически сброситься
   - Карты должны исчезнуть
   - Стол должен быть готов к новому раунду
   - В консоли должно быть сообщение:
     ```
     ✅ Все выплаты оплачены! Можно начинать новый раунд
     ```

4. **Проверьте обработку очереди (если есть)**
   - Если в очереди есть еще выплаты (например, пары)
   - Они должны обрабатываться последовательно
   - После каждой выплаты очередь должна обновляться

5. **Проверьте счетчик раздач**
   - Счетчик раздач должен увеличиваться только при начале нового раунда
   - Не должен увеличиваться при оплате выплат

### ✅ Ожидаемый результат:
- После оплаты всех ставок раунд сбрасывается
- Новый раунд можно начать сразу
- Очередь выплат обрабатывается корректно
- Счетчик раздач обновляется только при начале раунда

### ❌ Если не работает:
- Проверьте, что `process_payout_queue_or_reset()` вызывается
- Убедитесь, что `phase_manager.reset()` вызывается
- Проверьте логику в `PayoutQueueHandler.process_payout_queue_or_reset()`
